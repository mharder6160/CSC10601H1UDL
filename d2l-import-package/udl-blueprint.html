UDL Course Blueprint: CSC1060 Computer Science I (Java)

Course context and design intent

  • Course: CSC1060 Computer Science I: Java
  • Design use: Starter-shell foundation for Brightspace/D2L course build
  • Audience: First-term or early-programming students with varied coding experience
  • Delivery: Hybrid in the source syllabus; the shell supports in-class and out-of-class learning

UDL framework implementation

Engagement

  • Weekly opening context tied to practical Java tasks
  • Choice of context in selected coding prompts
  • Low-stakes checks before high-stakes submissions
  • Progress transparency through checklists and time estimates

Representation

  • Core concepts presented in plain language and worked examples
  • Vocabulary lists with student-friendly definitions
  • Optional trace-table or flow-view support
  • Common error examples with interpretations

Action and expression

  • Acceptable evidence can include runnable code, pseudocode notes, or test logs where appropriate
  • Rubrics separate correctness from communication, testing, and reflection
  • Larger projects can be scaffolded with milestones

Accessibility and inclusion

  • Page headings follow a logical order from h1 to h2 to h3
  • Links should be descriptive
  • Color should never be the only way to communicate meaning
  • Tables should include header rows and be used only for data
  • Video and audio items require captions or transcripts: [INSTRUCTOR CONFIRM]
  • Downloadable documents should be reviewed with an accessibility checker before posting

Predictable navigation pattern

  1. Overview, outcomes, and checklist
  2. Mini-lesson and worked examples
  3. Guided and independent practice
  4. Low-stakes knowledge check
  5. Assignment or project
  6. Reflection and preview

Learner choice and scaffolding

  • Core and challenge practice tiers
  • Optional enrichment resources
  • Starter-code expectation statements
  • Milestones for larger projects

Feedback strategy

  • Fast formative feedback on low-stakes checks
  • Assignment feedback anchored to rubric criteria
  • One feedforward note in each graded coding feedback cycle
  • Optional revision path with final percentages to be confirmed: [INSTRUCTOR CONFIRM]

Assessment alignment

Major outcome areas include syntax, data types and operators, control flow, methods, arrays, object-oriented ideas, file I/O and exceptions, and recursion.

  • Weekly concept or reading quizzes
  • In-class or lab activities
  • Programming projects
  • Midterm and final project components

  4. Attach existing project documents and revise instructions for clarity and accessibility.
