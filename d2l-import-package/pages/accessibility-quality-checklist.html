D2L Accessibility and Quality Checklist

Use this checklist before publishing each module/page.

A) D2L pages and documents

  • [ ] Headings follow logical order (H1 -> H2 -> H3)
  • [ ] Lists/tables use semantic structure
  • [ ] Link text is descriptive
  • [ ] Reading order is clear
  • [ ] PDFs/Docs pass accessibility checker (tagged headings, alt text, readable order)

B) Video/audio

  • [ ] Captions are available and accurate
  • [ ] Transcript provided for audio/video content
  • [ ] Visual-only information is also explained in narration/text

C) Code examples

  • [ ] Code is provided as selectable text (not only screenshots)
  • [ ] Monospace formatting used for readability
  • [ ] Variable names are meaningful and beginner-friendly
  • [ ] Example output included

D) Quizzes/knowledge checks

  • [ ] Clear instructions and point values
  • [ ] Question wording avoids unnecessary ambiguity
  • [ ] Time limits and accommodations reviewed ([INSTRUCTOR CONFIRM])
  • [ ] Feedback provided for low-stakes checks where possible

E) Visual design and color

  • [ ] Sufficient color contrast
  • [ ] Color is not the only method for emphasis or correctness
  • [ ] Font choices are readable and consistent

F) Keyboard and navigation

  • [ ] All essential interactions work by keyboard
  • [ ] No required unsupported scripts or inaccessible embeds
  • [ ] Module layout is consistent week to week

G) Links and media

  • [ ] No broken links
  • [ ] External links open predictably and are labeled
  • [ ] Download files have clear names and purpose

H) Final quality pass

  • [ ] Dates/due times match syllabus/schedule in D2L
  • [ ] Rubric attached to graded assignment
  • [ ] [INSTRUCTOR CONFIRM] placeholders resolved for student-facing release
