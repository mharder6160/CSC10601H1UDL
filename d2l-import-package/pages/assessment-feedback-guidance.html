Assessment and Feedback Guidance (UDL-Aligned)

1) UDL-aligned programming assignment rubric (reusable)

Use this rubric pattern for module programming projects.

Criteria Weight What to look for
Functional correctness 40% Program meets stated requirements and produces expected outputs
Code quality/readability 20% Naming, structure, indentation, and understandable logic
Testing/debugging evidence 20% Student demonstrates testing process and interprets results
Explanation/reflection 20% Student explains choices, limitations, or lessons learned

Performance level descriptors

  • Exceeds: Complete, correct, and well-explained with robust testing.
  • Meets: Core requirements complete and mostly correct with adequate testing.
  • Developing: Partial completion and/or recurring correctness issues.
  • Needs revision: Major requirements missing or non-runnable submission.

2) Revision/resubmission policy language (draft)

Students may revise selected programming assignments after receiving feedback. Revisions must include (a) corrected code, and (b) a short “what I changed and why” note. Resubmissions are due within [INSTRUCTOR CONFIRM] days of feedback. Maximum recovered points: [INSTRUCTOR CONFIRM].

3) Formative feedback strategy

  • Use weekly low-stakes checks with immediate answer feedback.
  • In code assignment feedback, include: 1. One strength 2. One priority fix 3. One feedforward step for next assignment
  • Return feedback quickly enough for reuse in subsequent modules ([INSTRUCTOR CONFIRM turnaround goal]).

4) Academic integrity and collaboration guidance (intro programming)

Integrity baseline

  • Students submit their own code unless collaboration is explicitly allowed.
  • Reusing code from peers/internet/AI tools without permission and attribution is not allowed.
  • Institutional policy and course-specific AI expectations both apply.

Collaboration guidance language

  • Allowed: discussing concepts, pseudocode, debugging strategies.
  • Not allowed: sharing full solutions, copying runnable code, submitting another person’s work.
  • If pair/group activities occur, individual accountability artifact required (short reflection, quiz, or oral check).
