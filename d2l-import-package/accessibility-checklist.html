D2L Accessibility and Quality Checklist

Use this checklist before publishing each module.

D2L pages and documents

  • Headings follow logical order from H1 to H2 to H3.
  • Lists and tables use semantic structure.
  • Link text is descriptive.
  • Reading order is clear.
  • PDFs and documents pass an accessibility checker.

Video and audio

  • Captions are available and accurate.
  • Transcripts are provided when needed.
  • Visual-only information is also explained in narration or text.

Code examples

  • Code is provided as selectable text, not only screenshots.
  • Monospace formatting is used for readability.
  • Variable names are meaningful and beginner-friendly.
  • Example output is included.

Quizzes and knowledge checks

  • Instructions and point values are clear.
  • Question wording avoids unnecessary ambiguity.
  • Time limits and accommodations are reviewed: [INSTRUCTOR CONFIRM].
  • Feedback is provided for low-stakes checks where possible.

Visual design and color

  • Color contrast is sufficient.
  • Color is not the only method for emphasis or correctness.
  • Font choices are readable and consistent.

Keyboard and navigation

  • Essential interactions work by keyboard.
  • No required unsupported scripts or inaccessible embeds are used.
  • Module layout is consistent from week to week.

Links and media

  • No broken links remain.
  • External links open predictably and are labeled.
  • Download files have clear names and purpose.

Final quality pass

  • Dates and due times match the syllabus and D2L schedule.
  • Rubrics are attached to graded assignments.
